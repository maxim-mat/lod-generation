# CityJSON surface triangulation (src/geometry/geometry.py::triangulate_face).
# mapbox-earcut is listed explicitly rather than via `cjio[export]`: that extra

# plain `pip install cjio` leaves the package importable but unable to

# Exact point-to-surface distances for the paired mesh metrics
# (src/eval/mesh_metrics.py::surface_distances). Sampling both meshes and doing
# point-cloud-to-point-cloud instead carries a ~sqrt(area/n) noise floor -- 0.129 m
# at n=4096, which was 126% of the real LOD1->LOD2 chamfer. Install `embreex`
# alongside if the proximity query becomes a bottleneck; it is a drop-in speedup.
trimesh>=4.0
# trimesh's ONLY hard dependency is numpy; everything else sits under extras, so
# `pip install trimesh` gives you a package that imports fine and then fails at
# the first proximity query. `closest_point` walks `mesh.triangles_tree`, which
# is an R-tree, so rtree is not optional for us even though it is for trimesh.
# Pinned explicitly rather than as `trimesh[easy]`, which would also drag in
# manifold3d and friends we do not use.
rtree>=1.0
# Exact CSG for src/analysis/exact_volume.py: vol(A\B) + vol(B\A) between a
# building's LOD1 and its LOD2. Nothing already here can do a 3D boolean --
# shapely is 2D, scipy has no CSG, and trimesh ships the API but no engine, so
# `trimesh.boolean.*` raises without a backend. Note the comment on trimesh
# above: manifold3d was previously avoided as an unused `trimesh[easy]` extra.
# It is now a direct dependency and used directly, not through trimesh.
#
# Feed it float64 via `Mesh64`, never the plain float32 `Mesh`. manifold3d sets
# its vertex-merge tolerance from the bounding box, so at EPSG:28992 magnitudes
# (y ~ 450,000) float32 gives a 5.4e-2 m tolerance -- it welds vertices 5 cm
# apart, and measured over 200 real pairs the symmetric difference drifts up to
# 4.4% (cancellation: an SD is a small difference of large near-equal volumes).
# Mesh64 takes that to 4.5e-7 m and 1.6e-8 relative.
manifold3d>=3.0
# Orthophoto I/O (src/ortho_download.py, src/ortho_parse.py, src/dataset/ortho.py):
# windowed reads resampled to a fixed size, tiled YCbCr-JPEG GeoTIFF writing with
# sparse blocks and overviews. Nothing above reads or writes georeferenced
# rasters; the Windows wheels bundle GDAL. Pinned below 1.5 because 1.5 requires
# numpy>=2, which the scipy here (1.13, numpy<2.3) does not allow; rasterio 1.4
# in turn breaks on affine 3.x (slotted Affine).
rasterio>=1.4,<1.5
affine>=2.3,<3
